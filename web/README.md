# oxsum web (React dashboard)

The standalone React frontend that will replace the Topcoat pages once it
reaches parity (issue #234). Vite + React 19 + TypeScript + Tailwind v4 +
TanStack Query, talking to the same `/api/v1` REST surface.

## Layout

- `src/api/client.ts` — fetch wrapper over the `{data}` / `{error}` envelope.
- `src/api/schema.d.ts` — generated by `openapi-typescript` from
  `crates/server/openapi.yaml`. Regenerate after any contract change:
  `npm run codegen`.
- `src/api/hooks.ts` — TanStack Query hooks over the typed surface.
- `src/api/ws.ts` — the `/ws/billing` socket: snapshot of in-flight holds,
  then `turnStarted`/`turnProgress`/`turnSettled`.
- `src/components/` — app shell and primitives styled by `src/index.css`,
  which maps the DESIGN.md tokens onto Tailwind's theme (`bg-primary`,
  `text-muted`, `border-line`, `mono`, …).
- `src/components/cult/` — vendored Cult UI components (the `halo-*` family,
  `rolling-number`, `copy-button`, `code-block`, `typewriter`,
  `dynamic-island`, `bg-animated-fractal-dot-grid`, …) — copy-in source, not a
  package. They speak the shadcn token names (`bg-background`,
  `text-muted-foreground`, `border-input`, `ring`), which `index.css` aliases
  onto the DESIGN.md palette.
- `src/components/ui/` — the shadcn `button`/`badge` sources the vendored
  components import.
- `src/pages/` — one file per dashboard page; `Auth.tsx` holds the session
  pages, `Admin.tsx` the operator console.

## Development

```bash
npm ci
npm run codegen
npm run dev          # vite dev server, proxies /api to localhost:3000
```

Start the backend separately (`cargo run -p oxsum-server` with `.env`), then
open the Vite URL — session cookies are same-origin through the proxy.

## Production

`npm run build` emits `dist/`; `crates/server/src/spa.rs` embeds it via
`rust-embed` and serves it at `/app` (client-side routes fall back to
`index.html`, hashed `assets/` get immutable caching). The Dockerfile's
`frontend` stage runs `npm ci`, `codegen` and `build`, so the release image
still ships one binary. `dist/` is git-ignored except the committed
placeholder `index.html`, which keeps the embed folder present on a fresh
checkout.

- [x] Bill rows carry `entryId` → `/verify` link; the ledger-head archive check
      is implemented (localStorage head + `GET /api/v1/log/consistency`)
- [x] Requests list (key/model filters in the URL, in-flight + settled, live
      `/ws/billing` socket)
- [x] Usage daily rollup with a CSS bar chart
- [x] API keys: list, create, revoke, constraints (budget, windows, RPM/TPM,
      concurrency, allowlist) + committed-percent column
- [x] Members: list, add by email, invitation links, role changes, remove,
      ownership transfer
- [x] Webhooks: endpoints, create (events, `balanceLowMinor`,
      `budgetThresholdsPercent`), deliveries, delete — the test-delivery call
      is not in the contract, so the UI checks deliveries instead
- [x] Statements: list, detail, PDF export link, log anchor
- [x] Org switcher + create organization
- [x] Session pages: register, login (GitHub OAuth when configured),
      verify email, forgot/reset password, device authorize, redeem invitation
- [x] Admin console (channels+prices, organizations+adjustments, in-flight,
      anomalies, margin, reconciliation, closings, statements, redemptions,
      tiers, discounts, audit, credentials) — operator-token gated
- [x] Admin metering bench — `/api/v1/metering/*` (hold / settle / release /
      one-shot bill) driven with a pasted service credential
- [x] Budget snapshot widget (`GET /api/v1/budget`) on overview
- [x] Anchored checkpoint display (`GET /api/v1/log/checkpoint`) and the
      operator verifying key (`GET /api/v1/log/key`) on the log page
- [x] Chat page — streams `/v1/chat/completions` with a per-browser `chat` key,
      model picker from `/v1/models`; tabs also drive `/v1/messages`,
      `/v1/embeddings` and `/v1/rerank` as billed one-shot probes
- [x] Manual hold/settle/release bench on the overview (`POST /holds`,
      `POST /settlements`)
- [x] Top up — manual rail, Stripe checkout redirect, redemption-code claim
      (`POST /topups`, `/topups/stripe`, `/redemptions`)
- [x] Pricing — the public catalog (`GET /pricing`), the estimate calculator
      (`POST /estimate-price`), signed price heads (`GET /log/price-head`)
- [x] Settings — account card, resend verification, server health
      (`/healthz`), delete account (`DELETE /users/me`)
- [x] Device authorization page previews the pending request
      (`GET /device/request`) before approve/deny; the other two legs
      (`/device/code`, `/device/token`) are the CLI's side of the grant and
      get no web UI by design — same for Stripe's server-to-server
      `/webhooks/stripe` callback
- [x] Bill rows open the proof bundle in-page (`GET /entries/{entryId}/proof`)
- [x] Admin covers statement ops (finalize / record payment / suspend), the
      organization suspend toggle, and user password reset
- [ ] Public `/verify` — stays server-rendered: verification must answer
      without trusting the server's own code, and a server-served JS bundle
      cannot certify that. `/verify` stays outside `/app` on purpose.
- [x] Accessibility pass: global `:focus-visible` ring in `index.css`,
      disabled/loading states on the button primitives, `PageState`
      (loading/empty/error/normal) on every page, `useReducedMotion` /
      `motion-reduce` in the animated Cult components

## API reads added for the SPA (0.60.0)

`GET /api/v1/org/members`, `GET /api/v1/holds`, `GET /api/v1/entries`,
`GET /api/v1/bills`, and `reservedMinor`/`spentThisMonthMinor` on
`GET /api/v1/balance` — the four reads the server-rendered pages drew
straight from core, plus the two overview figures no endpoint carried.
