# oxsum web (React dashboard)

The React dashboard — the oxsum UI. It reached parity and the Topcoat pages
retired to it (issues #234, #256), so this is now the only dashboard; the legacy
`/dashboard/*`, auth and `/admin` paths `301` here. Vite + React 19 + TypeScript
+ Tailwind v4 + TanStack Query, talking to the same `/api/v1` REST surface.
The console is internationalized (issue #507): `src/i18n.ts` wires
react-i18next with `en` + `zh-CN` locale JSON under `src/locales/`, the
browser's `navigator.language` detected behind a `localStorage` override, and
a header switch (`components/LanguageSwitcher.tsx`) flipping between them.
Pages translate through `useTranslation()`/`t()`; inline markup rides `<Trans>`.

## Layout

- `src/api/client.ts` — fetch wrapper over the `{data}` / `{error}` envelope.
- `src/api/schema.d.ts` — generated by `openapi-typescript` from
  `crates/server/openapi.yaml`. Regenerate after any contract change:
  `npm run codegen`.
- `src/api/hooks/` — TanStack Query hooks over the typed surface, one file per
  domain (`types.ts` holds the hand-written response shapes, `session.ts`,
  `billing.ts`, `org.ts`, `reports.ts` the hooks; `index.ts` re-exports all).
- `src/api/ws.ts` — the `/ws/billing` socket: snapshot of in-flight holds,
  then `turnStarted`/`turnProgress`/`turnSettled`, with exponential-backoff
  reconnect and a `dead` flag pages use to offer a manual retry.
- `src/components/` — the app shell and the design vocabulary. `ui/` is the
  single component layer split per domain (`money`, `surface`, `state`,
  `table`, `badge`, `form`, `controls`: buttons, inputs, select, tabs, switch,
  badge, card, table, progress, code block, …). Behavioral primitives are
  Radix (`@radix-ui/react-*`); the overlay/form/navigation pieces are
  vendored shadcn/ui sources (`components.json` is the registry config)
  rewritten onto the product palette — owned code, not an npm theme. Styled
  by `src/index.css`, which maps the DESIGN.md tokens onto Tailwind's theme
  (`bg-primary`, `text-muted`, `border-line`, `mono`, …), and re-exported by
  `ui/index.ts`. `LiveIsland.tsx` sits beside it.
- `src/pages/` — one file per dashboard page; `auth/` holds the session pages
  (`shared.tsx` carries `AuthCard`/`ErrorText`, one file per flow), `Admin.tsx`
  the operator console.
- `src/App.tsx` — the routes. Every shell page except the overview and device
  pages is a `lazy()` chunk inside `components/PageBoundary.tsx` (Suspense plus
  a reload prompt). `lib/chunk-reload.ts` reloads the tab once when a chunk is
  gone after a redeploy (issue #1092; `tests/chunk-reload.test.ts`).
- `src/i18n.ts` + `src/locales/{en,zh-CN}.json` — the i18n instance and its two
  resource files (flat `namespace.key` pairs, shared verbs under `common`).
  Every user-visible string is a key looked up through `t()`; add a key to
  both files together — a missing `zh-CN` key renders English, never a blank.

## Development

```bash
npm ci
npm run codegen
npm run dev          # vite dev server, proxies /api to localhost:3000
```

Start the backend separately (`cargo run -p oxsum-server` with `.env`), then
open the Vite URL — session cookies are same-origin through the proxy.

One build-time variable shapes the bundle: `VITE_SOLANA_RPC_URL` names the
JSON-RPC endpoint the Topup page's wallet-adapter pay button sends the
customer-signed transfer through (issue #1147), defaulting to
`https://api.mainnet-beta.solana.com`. It is a `VITE_*` read inside
`import.meta.env`, not an `OXSUM_*` server var — set it at `npm run build`
for an authenticated or devnet loop.

## Production

`npm run build` emits `dist/`; `crates/server/src/spa.rs` embeds it via
`rust-embed` and serves it at `/app` (client-side routes fall back to
`index.html`, hashed `assets/` get immutable caching). The Dockerfile's
`frontend` stage runs `npm ci`, `codegen` and `build`, so the release image
still ships one binary. `dist/` is git-ignored except the committed
placeholder `index.html`, which keeps the embed folder present on a fresh
checkout.

## API reads added for the SPA (0.60.0)

`GET /api/v1/org/members`, `GET /api/v1/holds`, `GET /api/v1/entries`,
`GET /api/v1/bills`, and `reservedMinor`/`spentThisMonthMinor` on
`GET /api/v1/balance` — the four reads the server-rendered pages drew
straight from core, plus the two overview figures no endpoint carried.

Invitation consent (#634): Members creates bound invitation links for both new and existing users. `/app/invite` previews the offered customer role, retains the one-time registration key and supports explicit signed-in acceptance. Password/TOTP login preserves the invitation return path. Browser desktop/mobile/keyboard evidence remains pending; the configured Turnstile widget is part of T23 portal completion.

Business profile (#756): `/app/business#business/profile` reads the effective
seller identity; `profileWrite` permits the owner editor. Complete replacements
carry the displayed revision, reason and a stable retry key. Explicit nulls
clear optional fields, and saved values supersede deployment defaults. Login
and both portal contexts share the public contact/help identity. Frontend build
and backend coverage passed; browser layout/keyboard/locale acceptance remains
pending in [the evidence record](../docs/roadmap/operator-launch/evidence/business-profile.md).

The Business Prices editor supports exact decimal model/conditional-rate drafts,
revision-bound saves and publication, default/customer schedules, model overrides,
confirmed schedule end/cancel and customer/draft preview. Pure financial input
checks run with `node --experimental-strip-types --test tests/sale-draft.test.ts`.
Browser evidence is tracked separately in the operator-launch execution ledger.

### Published credit bundles (#774)

Business **Credit bundles** reads immutable version history. Owner/finance can
publish or retire with an audited reason and unchanged-intent replay; other staff
have history only. Customer **Orders → New → Bundle** selects a published version
and displays the fixed purchase, promotion, expiry and refund consequences. The
order detail preserves the purchased version. Runtime/browser acceptance is
tracked in `docs/roadmap/operator-launch/evidence/bundle-offers.md`.

Plan payment authority (#776): `/app/plans` shows the customer's exact payable
period quote, confirmation and standing-order recovery; `/app/orders/:id`
retains its purchased period snapshot. The first period starts on paid activation;
manual renewal opens at the current UTC boundary. Renewal fees and old statement
debts remain separate (#777). Actual browser acceptance and final integration
are recorded independently from frontend compilation.
