## Behavior and boundaries

Consumption keys retain serving and their own attributed usage, entries, proofs, receipts and task status. They cannot manage keys, teams, mandates or webhooks, or read customer-wide balances, statements, reports or exports. Members see their created keys and shared unattributed history; account-wide document entries remain private. The method/path capability matrix fails closed. Explicit credential headers prevent cookie fallback, including malformed values. Mutation transactions recheck personal sessions, TOTP, selected context and current membership.

Core filtering precedes pagination. WebSocket delivery uses the same scope and refreshes authorization before delivery and on idle checks. Task poll/cancel/replay and cache identity bind the exact submitting key. Gateway balance headers and insufficient-funds balance details are retired; request/freeze/charge headers remain. Legacy unbound replay/cache records cannot expose sibling-key results. Full serving-context work remains T07/T13.

The public `/verify?sample` no longer reads a deployment customer's latest settlement using a nonunique display name. It embeds the existing public verifier fixture and expected hash. Tests verify the fixture with an unavailable database and prove a real customer named Acme Demo never appears in the sample.

The [capability inventory](../../../customer-capabilities.md) covers 194 OpenAPI method/path operations plus exports, WebSocket, public proof/share surfaces, cache and replay. No ledger-engine, migration or lockfile change.
