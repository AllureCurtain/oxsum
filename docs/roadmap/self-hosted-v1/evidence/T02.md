- Issue: [#593](https://github.com/AllureCurtain/oxsum/issues/593). Scenario: A03; ownership inspection denial supports A01.
- Base: `aadde114ca61cf97d5254ae3ea45d0a18e4542ba`. Code/test candidate: `f9ced4974b3432cdd80293f4e95046735798785f`, branch `feat/business-ownership`; subsequent documentation-only commit records this evidence.
- Environment: local-isolated, macOS arm64, Rust 1.99.1, PostgreSQL 17 in Docker, per-suite scratch databases. No paid provider/payment call or live migration.

## Observed behavior

`crates/core/tests/business.rs` reconstructs the real pre-0072 schema, creates a legacy customer/key, funds/settles its wallet, records usage and finalizes a genuine anchored statement. After migration, repeated migration and concurrent migration it compares customer/user/member/key, price, statement/line, deposit and usage records; balance remains 4,300,000 minor, the signed tree-head note and receipt proof are identical, and the old key still resolves to the same customer. Verification of the genuine receipt passes before migration; the serialized proof is identical afterwards.

Existing channels/plans map to the singleton business. Customer ownership lookups require the matching business ID. No staff is created, initialization remains null, second-business insertion and mutation of the migration receipt fail. New organizations acquire profiles within their creation transaction.

The 1,000-customer insertion/mapping smoke completed in 51.593458 ms in the focused run. It produced 1,001 mapped customers while ledger schemas stayed at one and the existing cached wallet retained its Arc identity. This checks lazy mapping/cache behavior, not the D09 throughput, memory or soak targets; those remain T27.

`crates/server/tests/business.rs` verifies both deployment inspection routes reject absent/customer credentials, permit the deployment token and return 404 for an unknown customer. `ownership_preview.rs` launches the actual binary against an empty database with invalid service/telemetry configuration: stdout is JSON only, stderr is empty, and neither the oxsum schema nor a ledger schema is created. Preflight runs before service configuration, telemetry, migration and provider preparation.
