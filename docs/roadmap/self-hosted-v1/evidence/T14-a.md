## Implemented behavior

Migration 0085 stores business-owned merchant accounts and immutable encrypted versions. Identity includes rail, test/live mode and provider account ID. The selected-version composite foreign key cannot reference another merchant. New merchants are disabled; owner-only mutations append complete credential versions or change checkout enablement. Current session/capability, mutation, immutable original response and redacted audit share one transaction. Exact retries recover the original result after subsequent rotation or disablement.

Owner/admin/finance/viewer can read redacted settings and paginated history. Customer, consumption/integration/deployment bearer and support access is refused. Credentials and ciphertext never appear in list/history or mutation audit. The trusted signing-context lookup requires explicit merchant/version coordinates and has no serializer or debug formatter. Historical secrets are checked at startup, including rotated versions, and missing/wrong encryption keys refuse startup.

Configuration validates rail-specific fields, recognized mode prefixes and destination-policy syntax locally. Saving makes no network call. Hyperswitch with Stripe is primary; direct Stripe and Airwallex retain compatibility labels. `locallyValidated` is not payment certification. The legacy checkout path is not redirected by this foundation; scoped durable intake/bootstrap and purpose-specific payment orders are separate required work.
