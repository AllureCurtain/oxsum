## Behavior and review

`ServingAccess` is one repeatable-read, read-only snapshot of the caller's authority: customer, optional exact consumption key, business, key model set, customer-tier model set, the business/group channel set and the tier request rate. A key that is missing, foreign, revoked or expired fails closed; `None` is reserved for an authenticated customer's personal catalog read. Model sets are sorted so the same value can bind a versioned cache context.

Every model surface resolves routes through the same access filter. `GET /v1/models`, customer pricing, estimates and direct signed-price checkpoint reads list only permitted models. A public alias requires permission for both the public name and the resolved upstream target, plus the selected channel; permission for an alias never widens an excluded target. Experiment variants and fallback hops re-check the selected public name, target and channel, so configuration cannot turn a denied original into an allowed request. The originally requested model is retained on a cache hit through the existing requested/served evidence fields.

Excluded channels are removed before any credential is opened, so a channel sealed under a different key cannot break a permitted route's resolution. Read-only customer visibility of historical exports and proofs is unchanged. Existing ledger identities and historical proof formats are untouched.

Generic async tasks admit through the same customer/key/group intersection and tier request rate. Status/cancel remain scoped to the exact originating key and the admitted endpoint snapshot. Task aliases and any signed mandate are explicitly refused before provider contact: the task record carries only the public model, and terminal settlement prices through `(channel, model, pinned)`, so alias-target pricing and mandate binding are not representable yet. T13 must implement complete task operation, price, evidence and mandate binding; this intermediate refusal does not claim task alias support.
