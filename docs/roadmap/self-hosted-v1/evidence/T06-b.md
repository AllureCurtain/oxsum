## Behavior and review

Public provider destinations require HTTPS and globally routable IPs. The current business owner or separately authenticated deployment recovery may approve an exact internal IP set; metadata/link-local/unspecified/multicast/reserved addresses remain refused. New/repointed endpoints default to public unless explicitly approved. Saving configuration performs no DNS or provider request.

All channel gateway/task/catalog/bill callers use `ProviderHttp`: resolve once, validate every answer, pin the address set, retain the TLS hostname, refuse any fallback DNS, disable proxies/redirects/Referer, and encode model/task IDs as path data. The bounded 128-client pool revalidates DNS before reuse. Auth/payments/customer webhooks and deployment moderation are separate integration contexts. No new proxy infrastructure is introduced.

The explicit owner connection check commits authority/audit/pending intent before one non-inference HEAD request. Only the creator receives internal coordinates; concurrent replay or interrupted pending intent never authorizes another send. The first terminal category/status is immutable. Results contain no response bodies, provider URLs or credentials. A 405 is reachable but unsupported HEAD, not an authentication/model certification.

New task submit captures endpoint/policy/sealed selected key; poll/cancel use that immutable snapshot after rotation. Migration 0079 preserves old rows and captures upgrade-time directory coordinates only, since historical submission coordinates did not exist. Old internal tasks receive no guessed permission. Drain pre-upgrade tasks, preserve sealing keys in backup/restore, and revoke credentials upstream if previously admitted tasks must lose provider access. Ledger identity and historical proof formats are unchanged.
