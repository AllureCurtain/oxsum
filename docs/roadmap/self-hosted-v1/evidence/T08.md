## Behavior and review

Books belong to the singleton business and contain complete per-model sale terms. Draft saves append revisions with an optimistic `expectedRevision`; published versions reference an exact immutable draft. A price group is a reusable sale book, not an additional stacked scope or consumption request group. Defaults and customer assignments pin published versions. Per-model resolution is override → assigned book → default book. Missing models fall through; explicit free prices win. One selected term supplies one discount; legacy customer discount rows never alter it.

UTC microsecond windows are half-open. Schedule creation, cancellation and replacement serialize on the business lock and reject overlaps in the same scope. Replacing appends an end event and a new schedule atomically; failed overlaps or audit abort both. Ending cannot be backdated, precede the schedule start, extend the original window or rewrite an existing end. Original windows and shortened ends remain readable. Already resolved snapshots are self-contained and cannot be changed by later configuration.

Owner/admin manage book content/publication/defaults; owner/finance manage individual customer assignments/overrides. Owner/admin/finance can read and preview. All endpoints require current personal business context, current membership and second factor where configured; machine credentials and customer sessions are refused. Mutation receipt, configuration and audit commit together. Exact replay returns the original result; changed input conflicts, and current authority is checked even on replay.

Strict sale prices exclude supplier costs at base and rule levels. The existing pure `Price` selects conditional whole sets and itemizes normalized usage. Unsupported or unknown dimensions are refused. One discount scales the complete numerator before a single ceiling division; integer overflows fail closed. Reused arithmetic now checks bill sum/discount multiplication and uses widened cache-subset summation. An explicit legacy preview requires exact channel/model/version, removes costs without changing the stored row, and preserves its legacy source identity.
