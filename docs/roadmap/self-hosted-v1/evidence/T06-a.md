## Behavior and review

Current business-context session/TOTP/capability checks, complete request binding, configuration, immutable result and audit share one transaction. Only owners can change connection/protocol/provider pools/billing credentials; owner/admin can manage prices, aliases, cache and fallback chains and read redacted provider metadata. Explicit machine credentials prevent cookie fallback. Foreign channel/credential/alias/model identifiers cannot escape the business scope. Exact retry returns the original resource/version after later edits; changed input conflicts. Request fingerprints are domain-separated HMACs under the sealing key, never plaintext secrets or unkeyed secret hashes. Sealing-key rotation intentionally conflicts pre-rotation retries.

Migration 0078 preserves existing channel/credential/price identities and sealed bytes, makes channel identity/business ownership immutable, and maps fallback chains to the default business. New destination/protocol changes require explicitly supplied keys and clear old billing credentials. Saves make no network call. Deployment recovery and business mutations share an independent configuration advisory lock, including concurrent pool removal. Direct and alias serving resolution read endpoint, prices and pool from one read-only repeatable-read snapshot; previously separate reads could mix endpoint/key generations during rotation. No network request holds a configuration transaction. Runtime secret-bearing Debug output is redacted.
